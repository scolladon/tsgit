# Internal building blocks

Internal building blocks that power the Tier-1 commands. Most are exported from `@scolladon/tsgit/primitives` for advanced composition (but **not** bound on `repo.primitives.*`); a few are **fully internal** — reachable only by the commands themselves — and are listed here to document how the porcelain works, not as a public surface. Each entry names the source file under `src/application/primitives/`; that file is the canonical reference for the signature.

Alphabetical.

### `applyChangeset`
`apply-changeset.ts`. Apply a computed working-tree changeset (writes, deletes, chmods). Every `add`/`update` target's entry name is validated against git's index-entry rules before anything is written — a hostile name aborts the whole apply, working tree untouched (git's own two-phase split between building the index in memory and checking it out). A write through a symlinked leading directory unlinks it and creates a real directory first, matching git; a delete through one is skipped silently, leaving the symlink untouched. The dirty-tree guard's per-entry probe (`checkDirty`) is fanned out through the `ioBound` concurrency pool rather than run sequentially — pure reads, so the fan-out is free to reorder; refusal arrays are still sorted into git's raw-byte path order afterward, independent of which probe lands first. Used by [`checkout`](../commands/checkout.md) and [`reset`](../commands/reset.md) (`hard`).

### `applyMergeToWorktree`
`apply-merge-to-worktree.ts`. **Fully internal.** Materialise a 3-way-merge outcome onto the working tree and index — clean outcomes are written through; conflicts get marker files (or a bare take-ours write for a symlink/gitlink pair) plus stage-1/2/3 index entries. Shares the same symlinked-leading-directory parity as `applyChangeset`: a write unlinks a symlinked leading component and creates a real directory first; a delete through one is skipped silently. The user-facing description of this shared behaviour lives on [`merge`](../commands/merge.md)'s "Conflict writes" section. Used by [`cherryPick`](../commands/cherry-pick.md), [`revert`](../commands/revert.md), [`rebase`](../commands/rebase.md), and [`stash`](../commands/stash.md) `apply`/`pop`.

### `atomicWriteFile` · `atomicWriteRef`
`atomic-write.ts`. **Fully internal.** `atomicWriteFile(ctx, path, content, onLocked)` is the generic lock-then-rename primitive for any single-file artefact behind a `<path>.lock`: exclusively create the lock file, write `content`, rename it onto `path`; a `FILE_EXISTS` contention calls the caller-supplied `onLocked(lockPath)` to produce the format-specific refusal (a locked ref vs. a locked commit-graph read differently), every other failure propagates unchanged. `atomicWriteRef` is `atomicWriteFile` specialised for ref updates (`onLocked` always produces `refLocked`). `writeObject` uses `ctx.fs.writeExclusive` directly for loose objects, which need no lock file at all. Used by [`updateRef`](update-ref.md), [`writeCommitGraph`](#writecommitgraph).

### `buildIndexFromTree`
`build-index-from-tree.ts`. Project a tree to a stage-0 IndexEntry list with stat-cache donor preservation. Each leaf's entry name is validated against git's index-entry rules before it is projected — a `.git` alias (and its NTFS/HFS+ forms) or a `.gitmodules` entry staged as a symlink throws `INVALID_INDEX_ENTRY`. Used by [`reset`](../commands/reset.md) (`mixed`), [`checkout`](../commands/checkout.md).

### `buildPack`
`build-pack.ts`. Construct a packfile from an enumerated object set. Returns the pack bytes, the trailer SHA, the object count, and `entries` — `serializePackfile`'s own per-entry crc32 and offset metadata, in `input.oids` order, so a caller writing a matching `.idx` reuses the offsets and checksums the serializer already computed instead of deriving them a second time. Used by [`push`](../commands/push.md), [`packObjects`](../commands/pack-objects.md), [`bundle`](../commands/bundle.md) (`create`).

### `collectRoots` · `collectRetentionRoots`
`commands/internal/fsck/roots.ts`. **Fully internal.** Shared root-collection machinery behind two different root sets. `collectRoots(ctx, universe)` is [`fsck`](../commands/fsck.md)'s own — refs, reflogs and the index, checked against a pre-built object `universe` so an unresolvable target is reported as corruption rather than silently dropped; every fault (unborn HEAD, a dangling symref, an unreadable reflog) is tolerated. `collectRetentionRoots(ctx)` is [`maintenance`](../commands/maintenance.md)'s `gc` task's Pin-H root set — the same collectors, no pre-built universe (gc is discovering the candidate set, not consuming a finished enumeration), and STRICT: a ref or reflog that genuinely isn't one still roots nothing, but any other fault (a permission error, `EMFILE`/`EIO`) rethrows and aborts the run — gc has no corruption report to fall back on, so a swallowed fault here would silently destroy a subgraph. Reflogs for `collectRetentionRoots` are read through a line-grained-lenient parse (a malformed LINE is skipped, the rest of the file still roots — pinned against git 2.55.0: `git gc --prune=now` keeps an object reachable only from a valid entry sharing a file with a garbage line) that still enforces the same `MAX_REFLOG_BYTES` cap `fsck`'s all-or-nothing `readReflog` does; the size cap itself is never tolerated. `collectRetentionRoots` also roots every OTHER worktree's own HEAD/reflog/index — the main worktree's when `gc` runs from a linked one, and every linked worktree's own registered under `<commonDir>/worktrees/*` — so an object reachable only from another worktree's (possibly detached) HEAD survives regardless of which worktree invoked `gc`.

### `compareWorkingTreeDelta` · `compareWorkingTreeEntry`
`compare-working-tree-entry.ts`. Compare one index entry against its working-tree file — the per-path building block behind [`status`](../commands/status.md)'s unstaged column, [`rm`](../commands/rm.md)'s dirty guard, and every stash/merge/cherry-pick/revert/rebase working-tree comparison. `compareWorkingTreeDelta` takes an index entry directly; `compareWorkingTreeEntry` resolves it from a path first. Both accept an optional index-file mtime that arms the `ie_match_stat` stat-cache short-circuit (only `status` supplies it). The optional shared stat map this entry used to describe (a cross-pass `lstat` memo populated by `status`'s untracked walk) was removed — every caller issues its own `lstat` again; a per-path memo shared across passes does not compose safely with the concurrent, `ioBound`-pooled dirty probes `applyChangeset`'s `checkDirty` now issues.

### `computeChangeset`
`compute-changeset.ts`. Tree-vs-working-tree diff for the dirty-tree guard. Used by [`checkout`](../commands/checkout.md), [`reset`](../commands/reset.md), [`status`](../commands/status.md).

### `computeClosure`
`internal/closure-engine.ts` (plus `internal/bitmap-binding.ts`, `internal/pack-bitmap-binding.ts`, `internal/midx-bitmap-binding.ts`, `internal/bitmap-container.ts`, `internal/pack-artefact-source.ts`, `internal/closure-not-marks.ts`, `internal/object-emit.ts`). **Fully internal.** The shared reachability closure [`revList`](../commands/rev-list.md) and [`packObjects`](../commands/pack-objects.md) both compose over the same `wants AND NOT not` question. The caller supplies a required `tier` (`'walk'` or `'bitmap'`) — the engine holds no default, since the two commands disagree on which to default to. `'bitmap'` prefers a usable multi-pack-index bitmap for the in-use generation, then a usable per-pack bitmap, decoding the EWAH streams and trusting them exactly as git trusts them — no digest check on this read path; verification stays in [`fsck`](../commands/fsck.md). Any fault along that path — none present, unreadable, structurally refused, or a decoded position out of range for the artefact it indexes — falls back to the walk silently: no error, no signal that the fallback happened. Object `path` is a walk-only product: a bitmap encodes reachability and each object's type, never a name, so `path` is always absent on the bitmap tier regardless of `objects`.

### `createPackRegistry`
`pack-registry.ts` (plus the internal `midx-source.ts`, `midx-binding.ts` and `pack-shared.ts`). Fully internal. Two independent memos, not one shared scan. A module-level store gate (`createStoreGate`) loads `objects/pack/multi-pack-index` (flat, else the `multi-pack-index.d/` chain) on its own — this is the memo `assertLoadable()` awaits ahead of **every** read, loose objects included, because canonical git dies during object-store setup on exactly one thing (a structurally self-inconsistent multi-pack-index) and this gate reproduces that death before any loose-vs-pack branch is reached. The directory listing and pack construction sit behind a second, separate memo, forced only by `lookup()`, `all()`, `health()`, `indexFaults()`, `midxHealth()`, and `midxBitmap()` — never by a loose-only read. Two consumer-visible behaviours follow from the split: a pack directory whose listing is refused (permission denied, say) no longer denies a loose read, only a pack-forcing call; and a pack directory that is a regular file — `ENOTDIR` — folds to an empty pack listing the same way a missing directory does, so it no longer denies a loose read either (git itself serves a loose read at exit 0 in this case, printing its own warning). The `packRegistry: skipping pack index with no pack file` warn lives inside the pack-listing memo, so it no longer fires on a loose hit — it still fires on any read that forces the pack store. The `packRegistry: discarding unusable multi-pack-index` warn lives inside the store gate itself, so it **does** still fire on a loose hit whenever the midx is unusable. When a midx loads, it is treated as **authoritative** for the packs it names: a pack the midx claims that is gone or unusable makes its objects report missing even though a sibling pack in the same midx still holds them, exactly like git; a pack the midx does not name is served by the ordinary per-pack scan as before. A `.idx` missing its sibling `.pack` is excluded from the generation at scan time (one warn, no I/O — the listing is already in hand); a `.idx` that is corrupt or unreadable is now classified lazily, the first time something touches that pack (a lookup, or a forced `health()`/`all()` walk), rather than eagerly for every pack at scan time. A pack whose index claims a requested object gets a memoised 12-byte header probe at lookup — signature, version (2 or 3), header-vs-index object count — and is skipped per pack if unusable (its objects report missing, other packs and loose objects still serve, no negative cache), mirroring git's open-time validation. Midx corruption follows git's own two tiers: a structurally self-inconsistent midx or chain layer denies every read through the `Context` — loose objects included — until the on-disk state changes; a merely-unusable one (too small, unreadable, an offset outside the file, a hash-version mismatch) is discarded with one warn and every read falls back to the `.idx` scan. [`fsck`](../commands/fsck.md) audits the same registry through a cache-bypassing `Context` view (the session delta cache is cleared, never a second registry) so an integrity check never gets an answer the cache masked for an object a fresh decode would refuse. `refresh()` clears both memos together — the store gate and the pack-listing scan — then retires and closes the outgoing pack set, so the next read re-probes the midx and the next `all()`/`lookup()` re-lists the pack directory; `dispose()` awaits any in-flight scan, closes every handle it ever opened, and is terminal; a `Context` that only ever hit loose objects never forced the pack-listing memo, so it disposes without ever listing the pack directory. One registry per session (keyed on `ctx.session`, not `ctx` itself, since ADR-722 — every Context derived from the same repository-open, including a linked worktree's own, shares the same registry instead of missing on every spread-derivation), behind every packed-object read ([`readObject`](read-object.md), [`readBlob`](read-blob.md), [`streamBlob`](stream-blob.md)) and `fsck`'s enumeration. The successor lookup (`nextOffsetForEntry`, `internal/pack-offset-table.ts`) prefers a present, loadable `.rev` unconditionally — the discriminator is artefact presence, not object count (ADR-720 retired the old `REV_INDEX_MIN_OBJECTS = 5000` threshold entirely): with a usable `.rev`, the answer is a binary search over `.idx`+`.rev` directly, O(log N) `DataView` reads and zero allocation, canonical git's own shape, and no O(n) table is ever materialised. A `.rev` that proves unusable MID-READ degrades the whole pack to the sorted fallback for every later query against the same table (never re-attempting the lazy lookup), logging once on the degrade; an absent or refused `.rev` falls back the same way from the start. When the `.rev` body does load, it is trusted exactly as git trusts it — no digest check on this path. The fallback sorts every offset directly into a `Float64Array`, comparator-free — the same job canonical git does with a radix sort when it has no `.rev` to read. The registry also exposes `midxBitmap()`, the accessor `computeClosure`'s bitmap tier consumes for the midx-bitmap preference; the per-pack bitmap fallback loads directly off the packs `all()` already lists.

Two further members support `maintenance`'s `gc` task (ADR-731/732/733): `fileNames()` returns every regular-file name the current generation's directory scan saw — the same set the sibling-marker checks (`.keep`/`.promisor`/`.mtimes`) already consult — so a caller classifies a pack by file class at zero extra I/O, never a second `readdir` of `objects/pack/`; `settleRefresh()` awaits every handle close a prior `refresh()` parked for background completion, without disposing the registry, so a caller about to unlink a retired pack can prove every reader has released it first. `deltaBaseCache` (`PackRegistry.deltaBaseCache`, keyed by `` `${packName}:${offset}` `` via `deltaBaseCacheKey`) is the offset-keyed cache of reconstructed OFS/REF-delta intermediates `object-resolver.ts` populates and probes through `internal/object-caches.ts` — see that entry for its sizing.

### `deriveContext`
`derive-context.ts`. **Fully internal.** The ONLY path for building a derived `Context` — every call site that used to hand-roll `Object.freeze({ ...ctx, someField: x })` goes through this instead (ADR-722), so the cache-identity decision is made in one reviewable place. Decides whether the derived `Context` keeps `ctx.session` (sharing every session-keyed cache — config, shallow set, commit graph, loose-oid fanout, pack registry, reftable stack, parsed-object memo, FlatTree cache, …) or mints a fresh one (starting all of them cold). A fresh session is forced when the derivation crosses a repository boundary — `changes.layout` present with a different resolved common dir (a submodule: a genuinely different repository), or `changes.fs` present with no `changes.layout` (no `layout` to prove it is still the same repository) — or when the hash algorithm changes (`changes.hash`/`changes.hashConfig`), since an oid-keyed cache is meaningless across a digest-width change; `keepSessionAcrossHashChange: true` overrides the hash-boundary rule for the two call sites (clone's and bundle-verify's peer-algorithm adoption) that provably swap the algorithm before any oid-keyed cache holds an entry. A worktree or main-checkout derivation changes `layout.gitDir` (a different admin dir) but keeps the same common dir, so it keeps the session. Used by `deriveWorktreeContext`, `deriveSubmoduleContext`, `deriveMainContext` (`list-worktrees.ts`), and every other Context-shadowing derivation.

### `enumerateObjects`
`enumerate-objects.ts`. Enumerate every object id in the database (loose ∪ pack-index), sorted and de-duplicated. Takes an optional `accessiblePacksOnly` flag (default `false`) that restricts the pack half to packs whose header gate passes — [`fsck`](../commands/fsck.md)'s own universe knob, not a general filter; the default preserves cat-file-like enumeration, since every other surface (git's `cat-file --batch-all-objects`, `count-objects`) still lists a refused pack's ids. The loose half's 256 fanout directories are scanned through the `ioBound` pool rather than serially, and every directory entry is filtered to exactly the right count of lowercase hex digits before it is synthesised into an oid — a quarantine temp file (`tmp_obj_XXXXXX`), a stray dotfile, or a wrong-width name under a foreign hash algorithm is no longer admitted as a phantom object id; an unfiltered filename previously could be, and `maintenance`'s `gc` task would cruft-candidate, pack, and then fail to read it back at its own post-write verify, wedging every future run on the repository. Used by `fsck`.

### `enumeratePushObjects`
`enumerate-push-objects.ts`. Diff local vs remote heads to compute the push-pack object set. Used by [`push`](../commands/push.md).

### `enumerateRefs`
`enumerate-refs.ts`. Every ref NAME this Context can see — delegates entirely to the seam's [`listRefNames`](#refstore--getrefstore), never `listRefs`, so no per-ref read/resolve happens only to have its value discarded. Used by [`describe`](../commands/describe.md), [`name-rev`](../commands/name-rev.md), [`push`](../commands/push.md), [`remote`](../commands/remote.md), [`bundle`](../commands/bundle.md) (`create`), [`fsck`](../commands/fsck.md), [`reflog`](../commands/reflog.md) (`expire`), [`revList`](../commands/rev-list.md).

### `expiryCutoff`
`expiry-cutoff.ts`. **Fully internal.** Resolves `gc.pruneExpire`'s date-expression grammar to a unix-seconds cutoff for the cruft-pack survival rule `mtime > cutoff` — see [`maintenance`](../commands/maintenance.md) for the caller-facing grammar and defaults. Resolves the keyword layer first, exactly as git's `parse_expiry_date` does: `never` (case- and whitespace-tolerant) and the exact-match `false` mean nothing expires; the exact-match `all` and `now` resolve to the maximum time, so everything — future-dated state included — expires. Uppercase `ALL`/`FALSE` refuse, as in git. Every other form (`yesterday`, ISO-8601, `@<epoch>`, `<n>.<unit>.ago`) delegates to `parseApproxidate`, and an expression neither layer parses refuses (`CONFIG_BAD_DATE_VALUE`) rather than being approximated — a mis-parsed expression would silently move a cutoff that can destroy data. Used by `maintenance`'s `gc` task.

### `fetchPack`
`fetch-pack.ts`. Smart-HTTP `git-upload-pack` exchange — discover refs, send `want`/`have`, receive pack. The received pack streams straight to a quarantine file, `objects/pack/tmp_pack_<6-char random>` — git's own on-disk shape — hashed incrementally as bytes arrive rather than buffered whole in memory (clone memory drops from O(pack) to O(window), ADR-728). Only once the trailer verifies against the incrementally-computed digest is the quarantine file renamed to `pack-<sha>.pack` and its `.idx`/`.rev` siblings written; a handled failure best-effort-unlinks the temp file, a hard kill leaves it behind, matching git's own survival posture. The rename falls back to a plain `rename` where an atomic one is unavailable (OPFS). Used by [`clone`](../commands/clone.md), [`fetch`](../commands/fetch.md), [`fetchMissing`](../commands/fetch-missing.md).

### `getSpawnCwd`
`path-layout.ts`. Working directory for a spawned child process (hook, signer, textconv, merge/filter driver): the work tree when the repository has one, else the gitDir — git's own bare hooks run with `PWD=<bare.git>`. Same value as [`getRepoRoot`](get-repo-root.md), distinct in intent: names the spawn contract so call sites stop restating its why-comment. Used by [`runHook`](run-hook.md), `signPayload`, `applyTextconv`, `runFilterDriver`, `runMergeDriver`.

### `invalidateConfigCache`
`config-read.ts`. Drop the in-memory `.git/config` cache. Use after an out-of-band edit. Keyed on `ctx.session` — not `ctx` itself — with mtime+size staleness detection layered on top (the same self-validating pattern [`invalidateIndexCache`](#invalidateindexcache) uses for `.git/index`), so a raw `ctx.fs.writeUtf8` past this call is still observed on the next read; in-flight stats for the same session are coalesced so the (up to eight) concurrent eager-gate finders share one `stat` rather than paying one each. `config-scoped-read.ts`'s per-scope sections cache (system/global/local/worktree) mirrors the same session-keyed, mtime-validated shape independently, and `invalidateConfigCache` drops both together. The operational gate-verdict memo (`memoizeGateVerdict`, consumed by `internal/repo-state.ts`'s `assertOperationalRepository`) is owned here for the same invalidation domain and is never left cached on rejection — a transient read fault must not permanently refuse every later command on the session.

### `invalidateIndexCache`
`read-index.ts`. [`readIndex`](read-index.md)'s parsed-`GitIndex` cache, keyed on `ctx.session` — not documented on `readIndex`'s own page since it changes no observable return value, only how often the file is re-read. Self-validating: the cache key is `(size, mtimeMs, mtimeNs, ino)` from `.git/index`'s own `stat`, so an externally-rewritten index is always a correctly-detected miss, never a stale hit — `mtimeNs` and `ino` both matter, since a second-resolution filesystem cannot otherwise distinguish two writes landing in the same clock tick. A raw file above `INDEX_CACHE_MAX_RAW_BYTES` (32 MiB) is read, verified and parsed fresh every call and never retained — a parsed `GitIndex` runs 3–5× the raw byte count, so caching one at unbounded size could retain the better part of a gigabyte for the Context's lifetime. `invalidateIndexCache` drops the entry unconditionally after `internal/index-lock.ts` commits a write — a same-tick write can produce a stat identical to what was already cached, so the write path cannot rely on the key alone to self-invalidate.

### `isWorkingTreeDirty`
`apply-changeset.ts`. Predicate over a computed changeset. Used by [`checkout`](../commands/checkout.md)'s dirty-tree guard.

### `limitFor` · `boundedMapFor` · `limiterFor` · `defaultLimitFor`
`internal/concurrency.ts`. **Fully internal.** The concurrency-policy seam every pool bound in the codebase resolves through (ADR-719) — no call site keeps a bare numeric bound of its own any more. `limitFor(ctx, bucket)` resolves one of two buckets, `'cpuBound'` or `'ioBound'`: an explicit `RepositoryConfig.parallelism` override always wins (a bare number applies to both buckets, `{ cpu, io }` overrides them independently with an absent member falling through); otherwise the bound comes from `ctx.concurrency` (resolved once at the composition root — `os.availableParallelism()`/`UV_THREADPOOL_SIZE` on Node, `navigator.hardwareConcurrency` in the browser, the safe floor everywhere else) or, absent that entirely, `deriveLimits({})`'s own floor. `boundedMapFor`/`limiterFor`/`boundedReaderFor` are `boundedMap`/`createConcurrencyLimiter`/`createBoundedReader` with their numeric limit replaced by `limitFor`'s policy — same input-order, rejection-propagates-without-cancelling contracts as before. `defaultLimitFor(bucket)` is the same floor with no `Context` to consult, for the handful of public, Context-free pipeline operators (`hashWorkdir`, `loadBlob`) that have no repository to derive a machine-backed bound from. Used throughout the primitives layer — `applyChangeset`, `diffTrees`, `detectSimilarityRenames`, `materialisePatchFiles`, `enumerateObjects`, `walkCommits`, the raw-tree walkers, `RefStore.packRefs`, the cruft-pack lifecycle, and more.

### `loadSparseMatcher`
`read-sparse-checkout.ts`. Compile `.git/info/sparse-checkout` to a `(path) => boolean` matcher. Used by [`sparseCheckout`](../commands/sparse-checkout.md), [`checkout`](../commands/checkout.md), [`reset`](../commands/reset.md).

### `longestStrictAncestor`
`src/repository/ceiling-stop.ts` (outside `application/primitives/` — layout resolution's own tier). **Fully internal.** The longest `ceilingDirs` entry that is a STRICT ancestor of the resolved cwd — the argument-array equivalent of `GIT_CEILING_DIRECTORIES`. Computed once, before the discovery walk starts, never per level. Because ancestry is strict, a ceiling equal to cwd (or equal to cwd *and* the resolved repo root) is a no-op rather than a refusal — the walk's first iteration always examines cwd. Entries are expected already resolved into the same coordinate system as cwd (the node shim realpaths both; sandboxed adapters compare lexically). Used by [`resolveLayout`](#resolvelayout).

### `materializeTree`
`materialize-tree.ts`. Apply a tree to the working tree (writes, deletes, chmods, symlinks). Used by [`checkout`](../commands/checkout.md), [`reset`](../commands/reset.md) (`hard`), [`merge`](../commands/merge.md) clean path.

### `parsedObjectMemoFor` · `cacheDeltaBase` · `probeDeltaBaseCache` · `deltaBaseCachingEnabled`
`internal/object-caches.ts`. **Fully internal.** Two caches [`readObject`](read-object.md)'s resolve pipeline consults, both keyed on `ctx.session` and both gated off entirely by `deltaBaseCachingEnabled` (`ctx.deltaCache.maxSize > 0`) — the gate `fsck`'s zero-budget audit `Context` trips, so an integrity check never reads from or populates state its own cache-bypassing view exists to avoid. **The parsed-commit/tag memo** (`parsedObjectMemoFor`, ADR-727): a byte-capped LRU (`PARSED_OBJECT_MEMO_FRACTION = 1/16` of `ctx.deltaCache`'s own byte budget, entry-capped at `PARSED_OBJECT_MEMO_MAX_ENTRIES = 65 536`) skipping the re-parse `resolveObject` would otherwise redo on every read even when the raw bytes were already cache-hot — populated only for commits and tags, whose parse cost is non-trivial (blobs/trees already return near-raw data). `forgetParsedObjectMemo` drops one oid — `maintenance`'s `gc` task is the first caller that ever removes an object, calling this for every oid it destroys so a destroyed commit cannot keep reading back successfully forever. **The delta-base cache** (`probeDeltaBaseCache`/`cacheDeltaBase`, ADR-736): the offset-keyed `PackRegistry.deltaBaseCache` of reconstructed OFS/REF-delta intermediates, sized at a FULL additional `ctx.deltaCache.maxSize` — additive, not a fraction of it, unlike its two siblings above. A probe hit still re-enforces `enforcePackBaseCap` against the caller's `maxBytes`, so a warm cache cannot serve past a cap a cold read would have refused at. With every cache in this family at its default (`ctx.deltaCache` 16 MiB, the parsed-object memo and [`read-head-tree`'s FlatTree cache](#readheadtree) each 1 MiB, the delta-base cache a full 16 MiB) the true combined ceiling a `Context` can retain is **~34 MiB**, not the ~16 MiB `deltaCacheMaxBytes` alone would suggest (ADR-736's amendment to ADR-726/727).

### `readConfig`
`config-read.ts`. Read `.git/config` (INI tokenizer; reused by `.gitmodules` parsing in submodules). A layout the ownership-trust gate refuses (`untrusted` or `implicitBare`) short-circuits before the file is opened — every consumer of the cached entry observes the same empty scope the acceptance tier is about to refuse on, rather than racing a malformed value in the attacker's file. A layout the sibling format gate refuses is **not** guarded here: the format verdict is itself derived from this same read, so by the time any caller reaches `readConfig` on a format-rejected repository, `assertAcceptedRepository` has already thrown.

### `readExistingCruftPack` · `computeCruftMtimes` · `decideCruftFate` · `writeCruftPack` · `retireCruftPack` · `declassifyCruftPack`
`internal/cruft-pack-lifecycle.ts`. **Fully internal.** The cruft pack's lifecycle for `maintenance`'s `gc` task (ADR-731) — discovering the existing cruft pack(s) and their `.mtimes` sidecars, computing mtime provenance for unreachable candidates, deciding what the next `gc` does to the cruft pack, and the physical write/retire operations that decision drives. `readExistingCruftPack` parses every pack `classifyPackFiles` puts in the `cruft` bucket (normally 0 or 1; a crash between the write step and the retirement step can leave two valid ones, both read and merged) — a `.mtimes` whose object count disagrees with its sibling `.idx`, or whose self-checksum fails, is a typed refusal (`INVALID_CRUFT_MTIMES`) that reads nothing further, never a silently empty map. `computeCruftMtimes` derives each candidate's age as the `Math.max` over up to three PRESENT sources — a loose file's own `lstat`, a carried-forward sidecar entry, and a superseded normal pack's own `lstat` for an object migrating out of consolidation — fanned across the `ioBound` pool, never a lookup-with-fallback and never the wall clock. `decideCruftFate` is a pure three-way set comparison, never a schedule: the survivor set unchanged from the existing single cruft pack's own key set is `'noop'` (byte-identical, same name, nothing rewritten); an empty survivor set is `'delete'`; anything else is `'rewrite'` under a fresh sha — the two-cruft-pack crash-recovery state can never take the `'noop'` branch, since the union always rewrites into one. `writeCruftPack` writes `.pack`/`.idx`/optional `.rev` via [`writePackArtifacts`](#writepackartifacts) then `.mtimes` LAST, mirroring retirement's own marker-last ordering — until `.mtimes` exists the pack reads as an ordinary one, never as a half-written cruft pack. `retireCruftPack` removes a superseded cruft pack's four siblings, `.idx` FIRST (removes it from every reader's candidate scan in one unlink) and `.mtimes` LAST (so the only reachable partial state reads as an ordinary pack with ages forgotten, never a sidecar with no pack); every removal is idempotent (absent is success). `declassifyCruftPack` drops only the `.mtimes` sidecar when a cruft pack's whole object set migrated intact into the normal pack under the identical (deterministic) sha — the pack bytes are not garbage, only the cruft classification is. Used by `maintenance`'s `gc` task.

### `readHeadTree`
`read-head-tree.ts`. Reads HEAD's tree, flattened (`flattenTree`) to a `FlatTree` — pure with respect to the working tree, only object reads. Exported from `@scolladon/tsgit/primitives` but not bound on `repo.primitives.*`. The result is memoised behind a byte-capped `LruCache` keyed `(rootTreeOid, maxDepth)` (ADR-726) — trees are immutable, so a repeat read of the same HEAD under the same `core.maxTreeDepth` never re-descends. Keyed on `ctx.session`, sized at `FLAT_TREE_CACHE_FRACTION = 1/16` of `ctx.deltaCache`'s byte budget with a floor-at-1 byte sizer, entry-capped, and gated by the same `deltaBaseCachingEnabled` check the [parsed-object memo](#parsedobjectmemofor--cachedeltabase--probedeltabasecache--deltabasecachingenabled) uses — a flattened tree is derived from object bytes, so it must not be served from or written into a memo `fsck`'s zero-budget audit `Context` shares. Gitlink entries (mode `160000`) are preserved in cached trees. An over-cap tree simply never caches, the same "accept the drop, document it" posture the parsed-object memo takes.

### `runGcTask`
`commands/internal/gc-pipeline.ts`. **Fully internal.** `maintenance`'s `gc` task itself — extracted from `maintenance.ts` to keep that file scoped to the command shell (option validation, task ordering, result assembly); see [`maintenance`](../commands/maintenance.md) for the task's observable contract (object placement by class, refusal conditions, `MaintenanceResult` fields). Owns the reachable/unreachable partition (over [`collectRetentionRoots`](#collectroots--collectretentionroots)' roots and `enumerateObjects`' universe), the normal/promisor/cruft pack builds (`buildPack` + [`writePackArtifacts`](#writepackartifacts)), reuse detection against the existing cruft pack (via [`readExistingCruftPack` and its siblings](#readexistingcruftpack--computecruftmtimes--decidecruftfate--writecruftpack--retirecruftpack--declassifycruftpack)), and superseded-pack retirement (`.idx`-first unlink ordering, midx expiry, `.rev`-sibling deletion). Post-write verification reads every oid this run packed back out with `verifyHash: true` passed explicitly — the one place in the codebase that opts back into hashing after ADR-718's default flip, since `gc` is about to delete the only other copy. Used by `maintenance`.

### `RefStore` · `getRefStore`
`ref-store.ts` (the reftable implementation lives in `reftable-ref-store.ts` and `reftable-transaction.ts`, documented separately below). **Fully internal.** The backend-neutral ref seam: `listRefs`, `listRefNames`, `resolveDirect`, `applyRefUpdates`, `readReflog`, `listReflogs`, `hasReflog`, `verifyIntegrity`, plus `packRefs` (the [`packRefs`](../commands/pack-refs.md) command's own verb). `getRefStore(ctx)` memoises one instance per `Context` in a module-level `WeakMap`, dispatching once — on `ctx.layout.refStorage` — to a files or reftable implementation.

Files backend: loose-first-then-packed lookup, with a `packed-refs` cache keyed on `mtimeMs:size` and a lazily-built by-name `Map` over its entries — built only the first time a point lookup (`resolveDirect`) actually needs it, so an enumeration-only caller (`listRefNames`, which walks `entries` directly) never pays to construct or retain it.

`listRefs` silently drops a loose ref whose content fails to parse (`verifyIntegrity` reports it instead); `listRefNames` deliberately does not — it never opens the file, so an unparseable ref still contributes its name. That is an enumeration CONTRACT, not a claim to match any one git command: measured at git 2.55.0 on a repository carrying one unparseable loose ref, `for-each-ref` and `branch` warn `ignoring broken ref` and omit it (exit 0), while `rev-list --branches` and `bundle create --all` refuse outright with `fatal: bad object` — git itself disagrees, so skip-or-refuse is the CALLER's policy, and each caller here already picks one (`rev-list`, `fsck`, `reflog expire` tolerate; `bundle create` propagates).

`applyRefUpdates` takes a `RefUpdate[]` — `set`, `setSymbolic`, `delete`, `reflogOnly` (a log entry with no accompanying ref write, e.g. a coupled HEAD's reflog line), and `reflogReplace` (a whole-history rewrite; the files backend's only way to express dropping or filtering existing entries — [`stash`](../commands/stash.md)'s `drop` is its one caller) — applied as one call, so a coupled write lands as a single observable mutation instead of two. Used by [`enumerateRefs`](#enumeraterefs), [`resolveRef`](resolve-ref.md), [`updateRef`](update-ref.md), [`writeSymbolicRef`](#writesymbolicref), [`listWorktrees`](#listworktrees), and the reflog family below — effectively every ref read or write in the codebase.

### `loadReftableStack`
`load-reftable-stack.ts`. Reads a reftable stack's `tables.list`, opens every table it names, and merges them into a `ReftableStack` view — the reftable backend's read-side counterpart to the files backend's `packed-refs` load, above. Memoised per repository (keyed off `ctx.session`, not `ctx` itself — every `Context` derived from the same repository-open that keeps the session, via [`deriveContext`](#derivecontext) — a linked worktree's own included — shares this memo instead of missing on every fresh spread) and per stack directory, invalidated on `tables.list`'s own `mtimeMs:size`; a bounded LRU (256 MiB of retained bytes or 64 stacks, whichever binds first) caps what a long-running process cycling through many worktrees keeps resident, since nothing else prunes an entry once its worktree goes away. A table missing between the `tables.list` read and its own open — compaction unlinks a merged table as the LAST step of its protocol, and reads are by path rather than a held descriptor — gets one retry (a fresh `tables.list` read, then every table it now names); still missing after that throws `INVALID_REFTABLE { check: 'tables-list' }`.

Two refusals here guard input git itself does not refuse the same way: a `tables.list` entry naming a path separator, a `..` segment, a NUL byte, or a leading dot is rejected outright, because git's own reader enforces no name grammar at all and follows a relative escape straight out of the reftable directory (an absolute path, measured, is silently ignored instead); and every table is `stat`-checked against a 64 MiB ceiling before it is ever read, never slurped in first, with the list itself capped at 4096 tables. Used by [`createReftableRefStore`](#createreftablerefstore) and [`applyReftableUpdates`](#applyreftableupdates).

### `createReftableRefStore`
`reftable-ref-store.ts`. **Fully internal.** The reftable backend's `RefStore` implementation: every read verb answers off a [`loadReftableStack`](#loadreftablestack)-loaded merge view. Ref lookup is newest-table-wins by name — a tombstone in a newer table shadows every older table's record for that same name, so a deleted ref reads as absent rather than as a deletion. Reflog lookup shadows by `(name, update_index)` instead, because a log tombstone reuses the entry's own index rather than a fresh one, so two different-index entries for the same name never shadow each other. `listRefs`/`listRefNames`/`verifyIntegrity` walk the stack (or stacks — a linked worktree owns a second one alongside the common dir's) rooted at each name's own per-worktree-or-common directory, so a linked worktree's HEAD or per-worktree pseudorefs never leak into another worktree's enumeration. `verifyIntegrity` reads each table independently of the eager stack load, so one structurally-broken table becomes its own `badReftableTable` finding rather than denying the whole audit; reftable has no raw per-ref text, so the files backend's `badRefContent` finding is structurally unreachable here. `applyRefUpdates` commits through [`applyReftableUpdates`](#applyreftableupdates).

### `applyReftableUpdates`
`reftable-transaction.ts`. **Fully internal.** The only place that mutates a reftable stack, replaying git's own stack-lock protocol step for step: acquire `tables.list.lock` (`writeExclusive`, jittered ~100ms-budget retries on `FILE_EXISTS`, never breaking a stale lock — one that outlives the budget surfaces `REFTABLE_LOCKED` naming the stack); re-read `tables.list` fresh (never the memo) and re-verify every update's `expected` against it, so the compare-and-swap always runs under the lock rather than against a stale read; write the new table to a randomly-named temp file and rename it to its final `0x…-0x…-<rand>.ref` name; write the new `tables.list` body into the lock file; rename the lock over `tables.list` — the SINGLE commit point. Every earlier step's residue (an orphan temp file, an orphan `.ref` file, a lock holding an unread body) is inert on its own, cleaned up by hand or by the next orphan sweep, never by this call. An update list spanning both the common stack and a linked worktree's own acquires both locks up front in a fixed order (common first, so two tsgit writers can never deadlock), verifies every stack's CAS before writing any of them, and commits each independently — matching git's own non-cross-stack-atomic guarantee.

Auto-compaction runs as this call's last, best-effort step: a geometric rule (factor 2 by size) picks a run of adjacent tables to merge; a lock conflict on any table shrinks the segment to what is actually free, and fewer than two lockable tables gives up silently; only `REFTABLE_LOCKED` from this step is swallowed, anything else still fails the whole call. A merge keeps every ref and log tombstone unless the segment reaches back to table 0 — the only case eliding one is safe, since dropping a tombstone from a mid-stack merge would resurrect an older table's now-shadowed record. [`packRefs`](../commands/pack-refs.md)'s own `packReftableStack` reuses the same lock/merge machinery to force a segment across the WHOLE stack on demand, then — under a fresh list-lock acquisition held across the whole scan — unlinks every `*.ref`/`*.temp` file the current `tables.list` no longer names, deferring `*.temp` cleanup for that pass whenever a `*.ref.lock` shows a compaction might still be mid-merge.

### `listWorktrees`
`list-worktrees.ts`. **Fully internal.** Enumerate the main worktree plus every linked worktree registered under `<commonDir>/worktrees/<id>/`, sorted by path. Used by [`worktree`](../commands/worktree.md).

### `readRepositoryFormat`
`src/repository/read-repository-format.ts` (outside `application/primitives/` — layout resolution's own tier). **Fully internal.** Reads `core.bare` / `core.worktree` / `extensions.*` from `<commonDir>/config` — plus `<gitDir>/config.worktree` when `extensions.worktreeConfig` is on — through the same `LayoutProbe` the discovery walk uses; no `include.path`, no global/system scope. A caller-supplied `commonDir` moves `<commonDir>` here to that override: the repository-format acceptance verdict, `objectFormat`, and `refStorage` all read from the overridden config, and `<gitDir>/config` itself never participates in any of the three, override or not — only `<gitDir>/config.worktree` (the `worktreeConfig` extension) is read from the gitDir. Runs *before* a `Context` exists, so `resolveLayout` can decide the work tree ahead of the first command. A malformed `core.bare` reports `'malformed'`; a valueless `core.worktree` reports `null` — the caller maps each to `CONFIG_BAD_BOOLEAN_VALUE` / `CONFIG_MISSING_VALUE`. The same pass also computes the repository-format acceptance verdict — `core.repositoryformatversion > 1`, or an `extensions.*` name git does not know at version 1 (or treats as v1-only at version 0) — and returns it as a carried `RepositoryFormatRefusal` rather than throwing; `resolveLayout` freezes it onto `RepositoryLayout.formatRefusal` for the command tier to read synchronously. One condition IS thrown here rather than carried: a top-level unbacked-extension entry (`compatObjectFormat`, `refStorage`) on a version-1 repository the verdict just accepted — tsgit cannot yet act on those extensions, so `REPOSITORY_EXTENSION_UNSUPPORTED` fires immediately, ahead of every config-porcelain read including `config --list`. Also resolved here: `extensions.refStorage` (`'files'` / `'reftable'`, defaulting to `'files'`), the same grammar shape and version-gating as `objectFormat` below — `resolveLayout` freezes it onto `RepositoryLayout.refStorage`, readable synchronously and consumed by ref-storage backend selection. Skipped entirely (an `EMPTY_FORMAT` substituted) when the layout resolution's trust gate has already rejected the repository — see [`resolveLayout`](#resolvelayout). Used by [`resolveLayout`](#resolvelayout).

### `resolveLayout`
`src/repository/resolve-layout.ts` (outside `application/primitives/` — layout resolution's own tier). **Fully internal.** The one layout-resolution algorithm every runtime shim shares: locates the gitDir structurally (an explicit `opts.gitDir`, or the discovery walk — which now also recognises `cwd` itself as a git directory, bare or not). `opts.commonDir`, when supplied, is resolved against `cwd` once, ahead of dispatch, and substituted into whichever route runs **before** candidate validation — an unusable override still fails the discovery route's `objects/`/`refs/` check (the walk climbs past it) while the explicit route stays lenient, as it already is for `gitDir`; a value equal to the resolved `gitDir` is normalised off the returned layout (`commonDir` stays absent) while still suppressing `core.bare` on the discovery and explicit routes. On a discovery/bare route (never on the explicit-`gitDir` route, which this gate always skips), it evaluates the ownership-trust verdict and the `bareRepositories: 'explicit'` implicit-bare predicate — both computed from the walk outcome and caller arguments alone, no file read; only when accepted does it read the repository-format keys via [`readRepositoryFormat`](#readrepositoryformat) — a rejected repository substitutes an empty format (`core.bare`/`core.worktree`/`extensions.*` all absent) rather than reading a file the caller was told not to trust; then decides the work tree by git's own precedence (`opts.workDir` beats `core.bare` beats `core.worktree` beats the route's own default) and derives `bare` as `core.bare is not false AND no work tree was resolved`. Returns the shape each shim (`index.node.ts`, `index.default.ts`, the browser's `resolveFixedEntryLayout`) finishes into a `RepositoryLayoutInput`, carrying `untrusted` / `implicitBare` / `foreignPath` / `formatRefusal` / `refStorage` alongside it. `refStorage` is REQUIRED (unlike the other optional fields here): every `Context` constructor — including the raw adapter factories, which never run this Stage-2 scan at all — must set it explicitly, defaulting to `'files'` by assignment rather than by omission.

### `writeCommitGraph`
`write-commit-graph.ts`. **Fully internal.** `maintenance`'s `commit-graph` task itself: sources every resolvable ref's peeled target via [`enumerateRefs`](#enumeraterefs) + [`resolveRef`](resolve-ref.md) (refs-only, Pin O — an unresolvable ref roots nothing rather than failing the whole write), walks them with [`walkCommits`](walk-commits.md), and hands the collected commit set to the domain writer (`serializeCommitGraph`, `commit-graph-writer.ts`) for the byte-identical assembly itself. ### `writePackArtifacts`
`internal/write-pack-artifacts.ts`. **Fully internal.** Writes a pack's sibling artefacts in git's own order: `.pack`, `.idx`, an optional `.promisor` sentinel, then `.rev` last — `.rev` last because pack discovery keys on the `.pack`/`.idx` pair, so a concurrent reader that observes the pair before the `.rev` lands just takes the absent-artefact arm. The `.rev` write is gated by `pack.writeReverseIndex` (default `true`), resolved *before* any file is created, so a value git's boolean grammar refuses leaves the pack directory untouched. `buildIdx`/`buildRev` (same file) assemble each artefact's bytes — a body/trailer split where `ctx.hash` fills the trailer in place. `packFilePath`/`cruftMtimesFilePath` are the shared path helpers every writer of `.pack`/`.mtimes` bytes agrees on (quarantine-rename callers and from-scratch writers alike); `buildCruftMtimes` assembles a cruft pack's `.mtimes` sidecar the same body/trailer way `buildRev` does, consumed by the cruft-pack lifecycle (see `readExistingCruftPack` below) rather than by this module's own `writePackArtifacts` call, which never writes `.mtimes` itself. Used by `fetchPack`, [`packObjects`](../commands/pack-objects.md), and the cruft-pack writer.
